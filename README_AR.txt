============================================================
اختبر معلوماتك العسكرية (فوج الحماية)
تصميم وإعداد: محمود عبد المعطي الأحمد
دليل الإعداد والنشر الكامل
============================================================

1) ما الذي يحتويه المشروع؟
---------------------------
المشروع موقع عربي متجاوب يعمل على الهاتف والكمبيوتر، ويتضمن:
- صفحة رئيسية احترافية.
- إدخال اسم المتدرب والرتبة والوحدة (الرتبة والوحدة اختياريتان).
- اختيار قسم محدد أو اختبار شامل.
- اختيار نوع الأسئلة: مختلط، اختيار متعدد، صح/خطأ، إكمال فراغ، كتابة.
- اختيار الصعوبة وعدد الأسئلة.
- خلط الأسئلة والخيارات في كل محاولة.
- مؤقت وشريط تقدم.
- تصحيح تلقائي ودرجة من 100.
- مراجعة الأخطاء والإجابات المقبولة بعد إنهاء الاختبار.
- حفظ أفضل نتيجة على جهاز المستخدم.
- حفظ النتائج في Supabase ليشاهدها المدير من أي جهاز.
- لوحة مدير لإضافة وتعديل وحذف الأسئلة والأقسام.
- استعراض نتائج المتدربين وحذفها وتصديرها بصيغة CSV.
- مظهر داكن وفاتح.
- دعم PWA: يمكن إضافة الموقع إلى شاشة الهاتف الرئيسية.
- توقيع ثابت: تصميم وإعداد محمود عبد المعطي الأحمد.

مهم: النسخة المرفقة تحتوي على أسئلة تجريبية تعليمية عامة وآمنة فقط. الأقسام الأخرى موجودة وجاهزة، ويمكن للمدير إدخال المحتوى التعليمي المسموح به من لوحة الإدارة.

3) التجربة السريعة دون قاعدة بيانات
-----------------------------------
يمكنك رفع الملفات مباشرة إلى GitHub Pages وسيعمل الموقع بوضع تجريبي.
في هذا الوضع:
- الاختبار يعمل بالأسئلة التجريبية الموجودة في js/demo-data.js.
- النتائج تُحفظ داخل متصفح الشخص فقط.
- لوحة المدير لا تعمل.
- النتائج لا تصل إليك.

لتفعيل لوحة المدير واستقبال النتائج يجب تنفيذ قسم Supabase أدناه.


4) إنشاء مشروع Supabase
------------------------
1. افتح https://supabase.com وأنشئ حسابًا.
2. اضغط New project.
3. اختر اسمًا للمشروع، مثل: protection-regiment-quiz.
4. أنشئ كلمة مرور قوية لقاعدة البيانات واحتفظ بها.
5. اختر المنطقة الأقرب إلى المستخدمين.
6. انتظر حتى يكتمل إنشاء المشروع.


5) إنشاء قاعدة البيانات
-----------------------
1. داخل مشروع Supabase افتح SQL Editor.
2. اضغط New query.
3. افتح الملف الموجود في المشروع:
   supabase/setup.sql
4. انسخ كامل محتواه والصقه في SQL Editor.
5. اضغط Run.
6. يجب أن تظهر رسالة نجاح.

الملف ينشئ:
- جدول admin_users للمديرين.
- جدول categories للأقسام.
- جدول questions للأسئلة.
- جدول results للنتائج.
- الفهارس وقيود التحقق.
- Row Level Security وسياسات الصلاحيات.
- الأقسام الأساسية.
- عدة أسئلة تجريبية عامة.

إذا شغّلت الملف مرة أخرى، فهو مصمم بحيث لا يكرر الأقسام والأسئلة التجريبية المعروفة.


6) إنشاء حساب المدير
--------------------
1. داخل Supabase افتح Authentication ثم Users.
2. اضغط Add user ثم Create new user.
3. أدخل بريدك الإلكتروني وكلمة مرور قوية.
4. فعّل خيار Auto Confirm User إن ظهر، حتى لا تحتاج إلى رسالة تأكيد.
5. بعد إنشاء المستخدم، انسخ قيمة User UID الخاصة به.
6. افتح SQL Editor ونفّذ الأمر التالي بعد استبدال النص بالـ UID الحقيقي:

insert into public.admin_users (user_id, display_name)
values ('ضع-هنا-معرف-المستخدم-UUID', 'محمود عبد المعطي الأحمد');

مثال شكلي فقط:
insert into public.admin_users (user_id, display_name)
values ('11111111-2222-3333-4444-555555555555', 'محمود عبد المعطي الأحمد');

لا تستخدم المثال؛ استخدم المعرّف الحقيقي من Authentication > Users.

إذا ظهر خطأ duplicate key فهذا يعني أن المستخدم مضاف سابقًا. للتحديث استخدم:

update public.admin_users
set display_name = 'محمود عبد المعطي الأحمد'
where user_id = 'ضع-هنا-معرف-المستخدم-UUID';


7) الحصول على رابط Supabase ومفتاح anon
---------------------------------------
1. داخل Supabase افتح Project Settings.
2. افتح API أو Data API بحسب واجهة Supabase الحالية.
3. انسخ Project URL.
4. انسخ المفتاح العام anon أو publishable key المخصص للمتصفح.
5. لا تنسخ service_role أو secret key مطلقًا إلى الموقع.

افتح الملف:
js/config.js

وعدله هكذا:

export const APP_CONFIG = {
  SUPABASE_URL: "https://YOUR_PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_PUBLIC_ANON_KEY",
  SITE_NAME: "اختبر معلوماتك العسكرية (فوج الحماية)",
  OWNER_NAME: "محمود عبد المعطي الأحمد"
};

احفظ الملف.

معلومة أمنية مهمة:
وجود رابط المشروع ومفتاح anon في كود المتصفح أمر طبيعي في Supabase. الحماية الحقيقية تعتمد على RLS التي أنشأها setup.sql. لا تضع service_role أو كلمة مرور قاعدة البيانات أو أي مفتاح سري في المستودع.


8) اختبار الموقع محليًا
-----------------------
لا تفتح index.html بالنقر المزدوج، لأن وحدات JavaScript قد لا تعمل عبر file://.
استخدم خادمًا محليًا.

طريقة Python:
1. افتح موجه الأوامر داخل مجلد المشروع.
2. نفّذ:

python -m http.server 8080

3. افتح المتصفح على:
http://localhost:8080

لوحة المدير:
http://localhost:8080/admin.html

أدخل البريد وكلمة المرور اللذين أنشأتهما في Supabase.

يمكن أيضًا استخدام إضافة Live Server داخل Visual Studio Code.


9) اختبار الوظائف قبل النشر
---------------------------
نفّذ الخطوات التالية:
- افتح الصفحة الرئيسية وتأكد من ظهور عبارة "متصل بقاعدة البيانات".
- ابدأ اختبارًا تجريبيًا باسم مختلف.
- أنهِ الاختبار وتأكد من ظهور النتيجة والتصحيح.
- افتح admin.html وسجل الدخول.
- تأكد من ظهور النتيجة داخل تبويب النتائج.
- أضف سؤال اختيار متعدد.
- تأكد أن الإجابة الصحيحة مطابقة حرفيًا لأحد الخيارات.
- افتح اختبارًا جديدًا وتأكد من ظهور السؤال.
- جرّب تعديل السؤال وإيقافه وحذفه.
- جرّب تصدير CSV.


10) رفع المشروع إلى GitHub
--------------------------
الطريقة من موقع GitHub:
1. أنشئ مستودعًا جديدًا.
2. يفضل اسمًا إنجليزيًا بسيطًا مثل:
   protection-regiment-quiz
3. اجعل المستودع Public إذا كان حساب GitHub المجاني لديك يتطلب ذلك لـ GitHub Pages.
4. لا تضف README تلقائيًا إذا كنت سترفع الحزمة كاملة، لأن المشروع يحتوي README.
5. افتح المستودع واضغط Add file ثم Upload files.
6. ارفع محتويات المجلد نفسه، وليس المجلد الخارجي فقط.
7. يجب أن يكون index.html في جذر المستودع مباشرة.
8. اضغط Commit changes.

الطريقة عبر Git:

git init
git add .
git commit -m "Initial release of protection regiment quiz"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

استبدل USERNAME وREPOSITORY بالقيم الحقيقية.


11) تفعيل GitHub Pages
----------------------
1. افتح المستودع في GitHub.
2. افتح Settings.
3. من القائمة الجانبية افتح Pages.
4. تحت Build and deployment اختر Source: Deploy from a branch.
5. اختر Branch: main.
6. اختر Folder: / (root).
7. اضغط Save.
8. بعد اكتمال النشر سيظهر رابط شبيه بـ:
   https://USERNAME.github.io/REPOSITORY/

إذا كان اسم المستودع USERNAME.github.io فسيكون الرابط:
https://USERNAME.github.io/

احتفظ بالملف .nojekyll في الجذر.


12) إعداد رابط الموقع داخل Supabase
-----------------------------------
داخل Supabase:
1. افتح Authentication ثم URL Configuration.
2. ضع رابط GitHub Pages في Site URL.
3. أضف الرابط نفسه إلى Redirect URLs، مع إضافة /* إن كانت الواجهة تقبل ذلك.

مثال:
https://USERNAME.github.io/REPOSITORY/

تسجيل الدخول بكلمة المرور يعمل عادة دون إعادة توجيه، لكن ضبط الرابط مفيد لإعدادات Auth المستقبلية.


13) استخدام لوحة المدير
-----------------------
افتح:
https://رابط-موقعك/admin.html

بعد الدخول ستجد:

أ) تبويب الأسئلة
- سؤال جديد.
- اختيار القسم.
- اختيار النوع والصعوبة.
- تفعيل أو إيقاف السؤال.
- كتابة نص السؤال.
- في الاختيار المتعدد: اكتب خيارًا في كل سطر.
- اكتب الإجابة الصحيحة أو الإجابات المقبولة، إجابة في كل سطر.
- أضف شرحًا يظهر بعد الاختبار.
- تعديل وحذف وبحث وتصفية.

ب) تبويب النتائج
- اسم المتدرب.
- الرتبة والوحدة.
- القسم والدرجة والوقت والتاريخ.
- فتح تفاصيل الإجابات.
- حذف النتيجة.
- تصدير النتائج الظاهرة بصيغة CSV.

ج) تبويب الأقسام
- إضافة قسم جديد.
- الاسم العربي.
- slug إنجليزي صغير مثل first-aid.
- أيقونة Emoji.
- وصف وترتيب وحالة النشاط.


14) قواعد إدخال الأسئلة
-----------------------
اختيار متعدد:
- خيار واحد في كل سطر.
- خياران على الأقل.
- الإجابة الصحيحة يجب أن تطابق أحد الخيارات حرفيًا.

صح/خطأ:
- الإجابة المقبولة يجب أن تكون "صح" أو "خطأ".

إكمال فراغ وكتابة:
- يمكن إدخال عدة صيغ صحيحة، صيغة في كل سطر.
- التصحيح يزيل التشكيل وبعض الاختلافات الإملائية الشائعة.
- الإجابات الطويلة لا يمكن تقييم معناها مثل الإنسان؛ أضف صيغًا مقبولة متنوعة.
- لا تستخدم سؤالًا مقاليًا مفتوحًا جدًا إن كنت تريد تصحيحًا آليًا دقيقًا.


15) الخصوصية والنتائج
---------------------
قبل بدء الاختبار يوافق المستخدم على حفظ اسمه ونتيجته لدى المدير.
النتائج ليست متاحة للزوار العاديين؛ سياسات RLS تسمح بعرضها للمدير فقط.

يوصى بما يلي:
- لا تطلب بيانات شخصية غير ضرورية.
- احذف النتائج القديمة دوريًا.
- لا تنشر ملفات CSV التي تحتوي أسماء دون حاجة أو إذن.
- أضف إشعار خصوصية يناسب الجهة التي تستخدم الموقع إذا كان الاستخدام رسميًا.


16) الأمن
---------
- استخدم كلمة مرور قوية لحساب المدير.
- لا تشارك حساب المدير.
- لا تضع service_role key في أي ملف عام.
- لا تعطّل RLS.
- راجع سياسات Supabase بعد أي تعديل في الجداول.
- اجعل المستودع خاليًا من الأسرار.
- مفتاح anon/public ليس سرًا، لكنه لا يغني عن RLS.
- إذا شككت بتسرب كلمة مرور المدير غيّرها فورًا من Supabase Authentication.


17) تحديث الموقع بعد النشر
--------------------------
بعد تعديل الملفات:
- ارفع الملفات المعدلة إلى فرع main.
- GitHub Pages سيعيد نشر الموقع تلقائيًا.
- إذا لم يظهر التحديث بسبب التخزين المؤقت، غيّر في service-worker.js:
  const CACHE_NAME = "mahmoud-quiz-v2";
  ثم ارفع الملف وأعد تحميل الصفحة.
- يمكن للمستخدم أيضًا حذف بيانات الموقع أو استخدام تحديث قسري.


18) تثبيت الموقع على الهاتف
---------------------------
Android / Chrome:
- افتح الموقع.
- افتح قائمة المتصفح.
- اختر إضافة إلى الشاشة الرئيسية أو تثبيت التطبيق.

iPhone / Safari:
- افتح الموقع.
- اضغط مشاركة.
- اختر Add to Home Screen / إضافة إلى الشاشة الرئيسية.


19) حل المشكلات الشائعة
-----------------------
المشكلة: تظهر عبارة وضع تجريبي.
الحل:
- تحقق من js/config.js.
- تأكد من صحة Project URL والمفتاح العام.
- افتح أدوات المطور Console لمعرفة الخطأ.

المشكلة: لوحة المدير تقول إن الحساب غير مسجل كمدير.
الحل:
- انسخ UID الصحيح من Authentication > Users.
- أضفه إلى admin_users عبر أمر insert الموضح سابقًا.

المشكلة: لا تظهر الأسئلة.
الحل:
- تأكد أن السؤال active.
- تأكد أن القسم active.
- تأكد أن إعدادات النوع والصعوبة تطابق السؤال.
- تأكد أن السؤال مرتبط بقسم موجود.

المشكلة: النتيجة لا تصل إلى لوحة المدير.
الحل:
- تأكد أن الصفحة تعرض "متصل بقاعدة البيانات".
- راجع جدول results في Supabase Table Editor.
- تأكد أن setup.sql �)
